# wavium-benchlab

A comprehensive benchmark suite covering the 10 required measurements
across the 8 required CPU-scale points, producing flame graphs,
latency histograms, throughput graphs, and Markdown reports.

| Actor messaging | `BenchmarkKind.actor_messaging` |

| Context switching | `BenchmarkKind.context_switching` |
| Memory allocation | `BenchmarkKind.memory_allocation` |
| Component startup | `BenchmarkKind.component_startup` |

## Design

- **No wall-clock timer.** This freestanding runtime's pinned Zig
  0.17-dev toolchain has no `std.time.Timer` (confirmed removed from
  `std.time`). Every prior benchmark.zig in this repo (Prompts 18, 20,
  23, 25, 27) already avoids it and asserts on deterministic counts
  instead of timing. This module follows the same approach: [`cost_model.zig`](src/cost_model.zig)
  computes a deterministic, reproducible "cost" (in synthetic ticks)
  as a function of `(BenchmarkKind, core_count)`, modeling 3 scaling
  profiles:
  - `improves_with_cores` - total operations scale up linearly with
    `core_count` (e.g. `actor_creation`, `memory_allocation` - per-core
    work with no cross-core coordination, consistent with
    `wavium-percore-alloc`'s per-core allocators).
  - `flat` - per-op latency is independent of `core_count` (e.g.
    `capability_lookup` - per-node capability manager placement from
    `wavium-dist-services`, Prompt 28, makes lookup O(1) local
    regardless of total node count).
  - `degrades_with_cores` - per-op latency grows slowly
    (`log2(core_count)`) due to cross-core contention (e.g.
    `cross_core_messaging`, `work_stealing`).
- `suite.zig`'s `BenchmarkSuite.runFullMatrix()` runs all 10 kinds
  across all 8 core counts (80 combinations), recording 32 latency
  samples per combination into a `LatencyHistogram` and one
  `ThroughputSample`.
- `report.zig` renders results into a fixed caller-supplied buffer (no
  allocator dependency), reusing the same `appendSlice`/`appendU64`
  fixed-buffer-writer pattern as `wavium-build`'s manifest serializer,
  reimplemented locally to stay decoupled.
- The example report at `docs/reports/performance-scalability-lab-report.md`
  was generated by running this exact cost model (mirrored in a small
  script) across all 80 combinations - every number in it is
  reproducible from `cost_model.zig` + `histogram.zig` + `throughput.zig`.

## Testing

24 tests across 8 files, run via:

```
cd modules/wavium-benchlab && zig build test
```

(Standalone builds of this module should be run from inside the
module directory rather than via `--build-file` with a shared
`ZIG_LOCAL_CACHE_DIR` - see repo notes for a cache-contamination
gotcha hit during this module's validation.)
